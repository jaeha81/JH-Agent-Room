JH Agent Room · Design Confirmation

Agent Room 앱화 및 전문 UI 4가지 안

아래 목업은 구현 방향 컨펌용입니다. Agent Room은 Claude와 Codex가 각각 독립 작업을 수행하고, 필요 시 자료를 상호 이관하며, 다른 한쪽이 교차 확인하는 운영 모델을 기준으로 합니다.

안 1. 웹 대시보드 전문화

현재 Node 서버와 브라우저 화면을 유지하면서 작업 큐 중심으로 정리합니다.

가장 빠름
localhost:3100 · JH Agent Room

장점

  • 현재 구조를 거의 유지
  • 리스크와 구현 시간이 낮음
  • 기존 Agent Room 큐와 바로 호환

한계

  • 완전한 데스크톱 앱 느낌은 약함
  • 서버 실행 상태를 사용자가 신경써야 함

안 2. Windows 런처 앱형

바탕화면 바로가기에서 서버를 시작하고 브라우저 Agent Room을 엽니다.

B안 포함

JH Agent Room

장점

  • PC 앱처럼 실행 가능
  • Electron 없이 가볍게 운영
  • 바탕화면 바로가기 제공 가능

한계

  • 실제 화면은 브라우저 기반
  • 업데이트/배포 자동화는 별도 설계 필요

안 3. Electron 데스크톱 앱

Agent Room을 독립 창으로 패키징하고 서버 제어를 앱 내부에 넣습니다.

2차 단계
JH Agent Room Desktop Sync OK

장점

  • 진짜 설치형 앱 경험
  • 서버 시작/중지 제어를 앱 내부화
  • 장기 제품화에 적합

한계

  • 패키징과 업데이트 관리 필요
  • 초기 유지보수 부담 증가

안 4. 운영 관제형 콘솔

채팅방보다 오늘의 작업, 이관 자료, 위험, 승인, 교차 확인 상태를 우선하는 지휘 화면입니다.

장기 목표
12Today
4Claude
3Codex
2Risk

장점

  • 대표/운영자 관점에 가장 적합
  • 승인, 위험, 교차 확인 대기를 한눈에 파악
  • 루틴 자동화와 잘 맞음

한계

  • 현재 채팅 중심 UX를 크게 바꿈
  • 데이터 모델과 상태 정의 보강 필요
Codex 추천: B안 유지 현재 단계에서는 안 1 + 안 2 조합이 가장 안전합니다. 즉, 현재 웹 대시보드를 전문화하고 Windows 런처로 앱처럼 실행하게 만든 뒤, Claude/Codex 양방향 작업 이관 흐름이 굳으면 안 3 Electron 또는 안 4 관제형 콘솔로 확장하는 순서가 적합합니다.
